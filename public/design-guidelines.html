Brillian Design System

Design Guidelines

One system for color across text, surfaces, and components — light and dark. The core idea: a neutral Ink ramp carries all text and borders, while the six brand families stay reserved for fills, surfaces, accents, and status. This keeps the cool Forest and warm Sand from clashing when they meet as type.

The one rule. Pull text and borders only from Ink. Use Forest / Sand / Brick / Coral / Citron / Lime for fills, surfaces, and accents — never for body text. Status uses Forest (success), Brick (error), and lightened steps in dark mode.

03 · Foundations

Borders

Borders are neutrals too — from the light end of Ink. Decorative edges can be featherweight; borders that signal state must clear 3:1.

TokenUse forHexOn white
border/subtleHairlines, dividers, row separatorsInk 100 · #E8E9E91.1 · decorative
border/defaultCard edges, containers, inputs at restInk 200 · #D1D4D21.5 · decorative
border/strongState-bearing edges, hover, dividers on tintInk 400 · #8289853.6 · UI ✓
border/on-darkBorders on Forest surfacesInk 700 · #33463Fdark only
Rule of thumb. Decorative borders can be featherweight (Ink 100–200); any border that conveys state — an input outline, a selected edge — must be Ink 400+ to clear the 3:1 non-text bar. Focus rings are the exception: they use Forest, not gray.

Radius

Radii ride the same 4px base grid as spacing. Two tokens do almost all the work — controls at 4px, cards at 8px — and both map directly onto Chakra's built-in base and lg steps.

control · 4px
card · 8px
pill · full
TokenChakra stepValueUse for
radius/controlbase4pxButtons, inputs, selects, checkboxes, chips
radius/cardlg8pxCards, panels, modals, popovers, menus
radius/pillfull9999pxTags, badges, avatars, toggles
Chakra setup. Chakra's default radii already includes 4px (base) and 8px (lg) — so you don't redefine the scale, you just override component defaults (which ship at md/6px) to point at the right step. The theme snippet is in the Tokens section.

Buttons WIP

Work in progress. Button variants, states, and the focus treatment are still being refined — don't build production components off this section yet. Colors and tokens may change. The Ink, Text, Borders, Radius, Inputs, and Cards sections are stable.

Five tiers of emphasis. Fills and borders carry the brand; every label comes from Ink. States move by darkening the fill, never by changing hue. Primary steps Forest 600 → 700 → 800; focus and pressed share the deepest step. Subtle is a neutral tonal fill (Sand 50 → 100 → 200) for low-emphasis actions like the one in a card header.

Focus — no ring. Focus is shown by shifting the fill to its deepest step: primary → Forest 800, destructive → Brick 800, secondary/tertiary → a Forest 100 tint. No outline, no inset. Focus shares the deepest fill with the pressed state — an accepted tradeoff for a ring-free look — and the shift is well over 3:1 from rest, so keyboard focus stays clearly visible. On dark, the primary lightens one step further (Forest 200).

Cards

The primary container in the app. A card is a padded, rounded surface that can hold a header (title, description, and an action area), a divider, and a body of content — most often a section header and form inputs. Every element is optional except the container itself — compose only the parts you need. Radius is always 8px; controls inside keep their own 4px.

Header — CardHeader: title (Manrope Medium 18, text/primary) + description (Manrope Medium 14, text/secondary), 4px apart. A right-aligned header-action area holds optional content — buttons, links, or info (e.g. a badge or timestamp).

Chakra theme

Register once, then eng uses <Card variant size> everywhere. Padding lives on the container and the header/body parts are reset, so one outer padding + gaps matches Figma exactly.

// theme/components/card.ts
import { cardAnatomy } from '@chakra-ui/anatomy'
import { createMultiStyleConfigHelpers } from '@chakra-ui/react'

const { definePartsStyle, defineMultiStyleConfig } =
  createMultiStyleConfigHelpers(cardAnatomy.keys)

const baseStyle = definePartsStyle({
  container: {
    borderRadius: 'lg',          // radii.lg = 8px  (semantic_tokens/card)
    bg: 'surface.bgSurface',     // #FFFFFF
    gap: 4,                      // 16px between header / body / footer
  },
  header: { p: 0 },   // padding lives on the container, not the parts
  body:   { p: 0 },
  footer: { p: 0 },
})

const sizes = {          // padding = card padding
  sm: definePartsStyle({ container: { p: 4 } }),   // 16px  (padding=small)
  md: definePartsStyle({ container: { p: 5 } }),   // 20px  (padding=medium)
  lg: definePartsStyle({ container: { p: 8 } }),   // 32px  (padding=large)
}

const variants = {
  elevated: definePartsStyle({                     // DEFAULT — resting card
    container: { boxShadow: 'shadow.sm' },          // 0 1px 2px rgba(0,0,0,0.15)
  }),
  raised: definePartsStyle({                       // actually elevated — floats
    container: { boxShadow: 'shadow.lg' },          // 0 8px 24px rgba(11,33,28,0.16)
  }),
  outline: definePartsStyle({
    container: { boxShadow: 'none', border: '1px solid', borderColor: 'border.subtle' },
  }),
  filled: definePartsStyle({                       // Brillian \"muted\"
    container: {
      bg: 'surface.bgCanvas',                      // #F6F5F3
      border: '1px solid', borderColor: 'border.subtle',
      boxShadow: 'none',
    },
  }),
}

export const cardTheme = defineMultiStyleConfig({
  baseStyle, sizes, variants,
  defaultProps: { variant: 'elevated', size: 'md' },
})

Usage

<Card variant=\"outline\" size=\"md\" w=\"360px\">
  <CardHeader>
    <Flex gap=\"2\" align=\"start\">
      <Box flex=\"1\">
        <Text textStyle=\"cardTitle\">Title</Text>
        <Text textStyle=\"cardDescription\" color=\"text.secondary\">
          Lorem ipsum dolor sit amet, consectetur adipiscing elit.
        </Text>
      </Box>
      {/* header-action: buttons, links, or info — all optional */}
      <Button variant=\"subtle\" size=\"sm\" leftIcon={<MailIcon />}>Button</Button>
    </Flex>
  </CardHeader>

  <Divider borderColor=\"border.subtle\" />

  <CardBody>
    <Stack spacing=\"3\">                          {/* content gap = 12px */}
      <Text textStyle=\"cardTitleSmall\">Optional section header</Text>
      <FormControl>
        <FormLabel>Email Address</FormLabel>
        <Input placeholder=\"Email address\" />
      </FormControl>
    </Stack>
  </CardBody>
</Card>
Handoff rules. Only the container is required — header, action area, divider, and body are all optional; compose what the use case needs. The header-action area can hold buttons, links, or info (badge, timestamp); keep it to a single logical group and align it to the top-right. Buttons here default to the subtle variant (neutral tonal fill) so they don't compete with the page's primary action. Use size for padding — never hardcode it. Keep the card radius at lg (8px) and leave inner controls at 4px; don't unify them. elevated is the default; reach for raised only when a card genuinely floats above the page (overlays, popovers, menus, a dragged card). Don't nest an elevated card inside another elevated card (shadow soup) — switch the inner one to outline. All card text is left-aligned. Title = cardTitle (18/Medium), description = cardDescription (14/Medium, text-secondary), section header = cardTitleSmall (16/Medium).
